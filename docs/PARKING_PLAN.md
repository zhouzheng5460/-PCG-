# 停车场布局与地块地面分割 —— 诊断与计划

日期：2026-11-04
状态：**待确认**（本文只出方案，不动代码）

---

## 一、现状诊断

### 1.1 车位尺寸是合规的

对照《汽车库建筑设计规范》JGJ 100—2015 与地方标准：

| 项 | 规范（小客车 90°） | 我们现在 | 判定 |
|---|---|---|---|
| 车位宽 | 2.4~2.6 m | **2.52 m** | ✅ |
| 车位长 | 5.3~5.8 m | **5.04 m** | 略浅（-0.3 m，可接受） |
| 通道宽 | 5.5~7.6 m | **6.3 m** | ✅ |
| 单车道净宽 | ≥ 4 m | 6.3 m | ✅ |

**所以"停车场不好看"不是尺寸问题。**

### 1.2 真正的问题：组织方式

| 问题 | 现象 | 根因 |
|---|---|---|
| **角度不统一** | 同一片停车里，这块 90°、那块 60°，车位线互相错开 | 求解器在 `axis / +30° / +45° / +60° / +90°` 里**逐片独立选最优**，只追求"塞得下最多车位"，不管相邻片的角度是否一致 |
| **树岛不对齐车位** | 树随机落在车位中间，看起来像"车停在树林里" | 树岛按"每 ~140 m² 一棵"均匀撒，完全不知道车位在哪 |
| **没有分组** | 一个 200 车位的地面停车场连成一片 | 规范要求每组 ≤ 50 辆、组间 ≥ 6 m（防火间距），我们没有这个概念 |
| **没有绿化率** | 停车区是纯沥青 | 规范：≥ 30 车位时，停车区的 **5%** 应为绿化（草/树/雨水设施）|
| **没有临街绿带** | 停车场直接怼到人行道 | 规范：临街停车区与道路边界之间需 **≥ 1.0 m** 软质绿化带 |
| **人行通道不贯穿** | 从车位走到店门要穿车流 | 规范：≥ 30 车位时需**贯穿停车区**的人行通道直达主入口；只有大地块才有 |
| **无障碍/充电缺失** | 没有专用车位 | 规范：无障碍车位宽 3.7~4.1 m 且靠近入口；充电桩 ≥ 10% |

### 1.3 一句话总结

**尺寸对了，但它是"塞车位"而不是"设计停车场"。**
真实停车场是**模块化**的：双排背靠背 + 一条通道 = 一个停车组（约 40~50 位），
组与组之间用树岛/绿化分隔。我们缺的是这个"模块"概念。

## 二、地块地面分割（ground program）的问题

现在的 `GroundProgram` 有 25 项，但对停车相关的只有三个：
`parking` / `employee_parking` / `service`。

对照规范，至少还缺：

| 该有的 program | 用途 | 现状 |
|---|---|---|
| `parking_aisle` | 车行通道（与车位面区分，画标线/材质不同） | 通道"不单独成面"（早期为了避重叠而合并进 parking） |
| `parking_island` | 树岛/绿化岛（车位组之间） | 没有；树是纯配景，不属于 ground |
| `parking_accessible` | 无障碍车位（靠近入口、加宽） | 没有 |
| `landscape_buffer` | 临街 1 m 绿化带 | 只有工业有，零售/住宅没有 |

**这直接影响"看起来像不像专业方案"** —— 专业总图上：
车位（深灰）+ 通道（略浅）+ 树岛（绿）+ 临街绿带（绿，连续一条）
是**四种明确区分**的面。我们现在只有一种（全深灰）。

## 三、计划（分三期，每期可独立验收）

### P1 · 停车模块化（Realizer 层）— 推荐先做

**目标**：让停车区从"自由排布"变成"模块拼装"。

```
一个停车模块 = 双排背靠背车位（各 5.04 m 深）
              + 中间 6.3 m 通道
              = 16.4 m 深 × N 长的条带
```

做法：
1. 在 `parking.ts` 的 `solveParking` 里，先按"模块条带"铺，再在剩余不规整区域
   用单排补（单排也强制与主角度一致）；
2. **角度由整个停车区统一决定**（按面积加权投票），不再逐片独立选；
3. 模块之间留 6 m（规范防火间距，也是树岛的位置）。

验收：
- 同一片停车区内，车位角度 100% 一致；
- 每个模块的车位数 40~50；
- 车位线不再互相错开。

### P2 · 树岛与绿化率（Realizer 层）

1. 树岛**放在模块之间**（6 m 带正中），不再随机撒；
2. 停车区绿化率 ≥ 5%（规范），不够就从模块间带补；
3. 临街侧加 1.0 m 连续绿带（新的 `landscape_buffer` 面）。

验收：截图里"车位组 — 树岛 — 车位组"能读出节奏；绿化率可算。

### P3 · 停车区组织与专用车位（archetype + program）

1. 大场地**分组**（每组 ≤ 50 位，组间 6 m）；
2. 新增 ground program：`parking_aisle` / `parking_island`（现在的 `parking` 拆开）；
3. 无障碍车位（靠近主入口 2~4 个）+ 充电车位（≥ 10%，画绿色标线）。

验收：专业总图四色分明（车位/通道/树岛/绿带）。

## 四、取舍与风险（先说清楚）

| 事项 | 代价 |
|---|---|
| **车位数会减少 10~15%** | 模块化 + 树岛 + 分组都要占地。现在 retail 的停车占比已经压在下限附近，可能触发更多 `PARKING_TIGHT` |
| **`parking` 面拆成三个 program** | 会改 `GROUND_MATERIAL`、`Realizer` 的归属切割、以及 `exclusiveOverlapRatio` 的口径 —— 需要一起跑一遍 |
| **强度带要重定** | 停车占地变化 → 覆盖率变化。这件事本来就排着（见 OPEN_ISSUES §5.3） |
| **不影响 Planner 的决策** | 三期全在 Realizer 与 program 定义层，`SitePlanCandidate` 的 `parkingRequests` 结构不变 —— **Planner 不需要重跑** |

---

## 五、建议顺序

1. **P1 停车模块化** —— 收益最直接（角度统一 + 模块化一眼能看出"这是设计过的停车场"），
   且不动 program 契约；
2. **P2 树岛对齐 + 绿化率** —— 依赖 P1 的模块位置；
3. **P3 拆 program + 专用车位** —— 动契约，放最后。

**建议先做 P1+P2 一起（约一轮），P3 单独一轮。**

请确认是否按这个顺序做，或者你想先做 P3 的 program 拆分。

## 六、实施记录：P1 + P2（2026-11-04）

### 6.1 一个意外发现：模块化其实早就有了

读代码发现 `layoutAt` 已经是**双排背靠背 + 中间通道**：

```ts
const pitch = l * 2 + aisle;   // 一个模块 = 两排车位 + 一条通道
```

两排车头都朝向中间那条 aisle，是标准的 double-loading。
所以 P1 不需要重写铺设算法 —— 真正坏掉的是**组织方式**。

### 6.2 真正的两个问题

| 问题 | 根因 |
|---|---|
| **角度不统一** | 每个停车面用**自己的最长边**当主朝向（`longestEdgeAngle(usable)`），相邻两片可能一片 90°、一片 60° |
| **树岛随机撒** | `scenery` 按面积均匀撒，完全不知道车位在哪 |

### 6.3 改法

**① 全局朝向（`globalParkingAxis`）**

所有停车面的最长边方向先折到 0~90°（车位朝向有 90° 周期），
再**按面积加权**投票（10° 一档）。面积加权很关键 ——
一个 5000 m² 的主停车面不该被旁边 200 m² 的碎角带偏。

每个面都从这个朝向出发，最多偏 45°（斜列兜底）。

**② 树池带（`layout.islands`）**

`layoutAt` 里沿车位排每 **6 个车位插一条 1.5 m 树池**，只占车位排、不穿通道。
代价约 9% 的车位，换来整个场地的观感。

**③ 树由 parking 种，不由 scenery 撒**

`realizeParking` 拿到 `layout.islands` 的真实位置，**隔一条树池种一条**
（每条都种会变成"一道绿篱横穿停车场"），树冠缩到 0.42。
`scenery` 里那段随机撒的逻辑删掉了。

### 6.4 效果

第一张是改前（角度歪、树随机散），第二张是改后：
车位线整片一致，树按车位组排成行、每十几位一组。

### 6.5 还没做（P3）

- 停车区分组（每组 ≤50 辆 + 6 m 防火间距）—— 我们的场地通常 20~60 位，
  一组就够，暂时不需要；
- `parking` 拆成 `parking_aisle` / `parking_island`（专业总图的四色区分）；
- 无障碍车位（3.7~4.1 m、靠近入口）、充电车位（≥10%）。
